# Maj_proj — NIR-based Blood Glucose Calibration

This project trains a calibration model that maps NIR sensor readings (from a MAX30102) to blood glucose (mg/dL), saves model coefficients, and uploads them automatically to an ESP32 device running `maj_proj.ino`.

The repository contains:

- `train_model.py` — Trains calibration models using the dataset, selects the best model (single-feature linear or quadratic on NIR), writes `model_coeffs.json`, and can upload automatically to the ESP32 over serial.
- `upload_model.py` — Helper to push `model_coeffs.json` to the ESP32 (dry-run and real upload modes).
- `maj_proj.ino` — ESP32 firmware that reads MAX30102 (NIR) and computes predicted glucose using the uploaded model coefficients. Supports two payload formats:
  - Legacy single-feature polynomial: `glucose = a*(x^2) + b*(x) + c` where `x = rawIR / scale`.
  - New 14-coefficient polynomial (multi-feature) — kept for compatibility but the training script currently uses the single-feature mode.
- `model_coeffs.json` — Last-saved model coefficients (generated by `train_model.py`).
- `NIR_Blood_Glucose.csv` — Source dataset used to train the models.

Goals implemented
- Train on only the first 120 rows of the CSV and use only the columns `NIR VALUE` (input) and `GLUCOSE(mg/dL)` (target).
- Train and compare two models: normalized linear and degree-2 polynomial on normalized NIR.
- Save coefficients in a legacy-compatible format (`coef_a`, `coef_b`, `intercept_c`, `scale`) so the ESP32 can apply the model directly.
- Automatic upload support from Python to ESP32 (`train_model.py --auto-upload` or using `upload_model.py`).
- ESP32 sketch updated to apply the same normalization before using model coefficients, and to accept both legacy single-feature and new multi-feature payloads.

Requirements
- Windows PowerShell (examples use PowerShell syntax)
- Python 3.8+
- For PC-side upload: `pyserial`
- Python libraries: numpy, pandas, scikit-learn
- Arduino IDE or PlatformIO to flash `maj_proj.ino` to the ESP32

Quick setup (PowerShell)

```powershell
# create venv (optional but recommended)
python -m venv .venv
& .\.venv\Scripts\Activate.ps1
pip install --upgrade pip
pip install numpy pandas scikit-learn pyserial
```

Train, inspect payload (dry-run)

```powershell
# train on first 120 rows and print payload
python train_model.py --dry-run-upload
```

This prints the model comparison, chosen model, saves `model_coeffs.json`, and prints the JSON payload that would be sent to the ESP32. The JSON payload for the legacy single-feature model will look like:

```json
{"model":"poly2","coef_a":-96.8176,"coef_b":567.2537,"intercept_c":-675.2035,"scale":100000,"r2":...,"rmse":...}
```

Upload model to ESP32

- Auto-detect & upload (convenient):

```powershell
python train_model.py --auto-upload 
```

- Upload to a specific COM port (e.g., COM6):

```powershell
python train_model.py --port COM6 
# or use the helper script
python upload_model.py --file model_coeffs.json --port COM6 --baud 115200 
```

Notes about the payload and formats
- Current training pipeline uses single-feature NIR normalization by dividing raw NIR by `scale` (default 100000). The trainer writes `coef_a`, `coef_b`, and `intercept_c` (for poly model) or only `coef_b`/`intercept_c` for linear.
- The ESP32 expects legacy single-feature keys for the single-feature model and computes:

  x = rawIR / scale
  glucose = a*x*x + b*x + c  (if a provided) or glucose = b*x + c (linear)

- The ESP32 also supports a 14-element polynomial payload (`coef_poly`) for the more advanced multi-feature model; this project currently focuses on the single-feature mode for simplicity and compatibility.

ESP32 firmware: Serial commands
- GET
  - Prints current model, coefficients, and scale.
- Upload JSON payload (single-line) — examples:
  - Legacy single-feature model:

    {"coef_a":-96.8176,"coef_b":567.2537,"intercept_c":-675.2035,"scale":100000}

  - New multi-feature payload (14 coefficients) — example format (single-line):

    {"coef_poly":[c0,c1,...,c13],"intercept_c":<float>,"scaler_mean":[...],"scaler_scale":[...],"r2":...,"rmse":...}

After sending a valid payload the ESP32 will reply confirming the coefficients were saved and will persist them in Preferences (nonvolatile).

Flashing the ESP32
- Use Arduino IDE / PlatformIO to open `maj_proj.ino`, select the correct board & COM port and Upload.
- After upload, open Serial Monitor at 115200 baud to see startup messages and the loaded model.

Troubleshooting
- Large negative predictions (e.g. -10000+): this is typically caused by a mismatch between how the trainer scaled/processed inputs and how the ESP32 applies inputs. The current workflow normalizes by `scale` and the ESP32 now applies the same normalization for the single-feature mode.
- If readings look shifted by a constant: ensure `scale` in `model_coeffs.json` matches what the ESP32 printed on boot (the trainer writes scale into the JSON and uploader sends it).
- ``pyserial`` errors: ensure your virtual environment is activated and `pip install pyserial` succeeded.
- Serial port in use: close any Serial Monitor or other program using the COM port before uploading from Python.
